# Upload a Clipcrow clip to YouTube

Uploads one finished clip through **YouTube Studio in the browser**, not the Data API. The user may have
no OAuth client configured, and the manual route avoids the API's private-until-audited restriction
and its ~6 uploads/day quota.

## Hard rules

1. **Never publish without a per-upload go-ahead.** Show the clip number, the exact title, the
   visibility and the file, then wait for a clear yes. One approval covers one clip, never a batch.
2. **Never sign in.** If Studio shows a sign-in or account chooser, stop and ask the user to sign in
   themselves. Do not type credentials, and do not pick an account on their behalf.
3. **Check the channel before uploading.** Studio can be pointed at the wrong channel. Confirm which
   channel is active and say so in the approval message.
4. If anything on the page is unexpected (a strike notice, a copyright claim, a changed layout),
   stop and describe it rather than clicking through.

## Faster route: the Chrome extension

`extension/` loads unpacked in Chrome and does steps 1, 5 and 6 for you: tick one or more clips in
its popup, press **Stage N clips**, then press **Fill from Clipcrow** on the Studio page; Fill opens Create -> Upload videos by itself. A queue is
walked one clip at a time — fill, publish, press **Next** — so each video is still seen before it
goes live. It attaches the MP4, types the title and
description from `caption.txt`, and sets *not made for kids*. The rules above still hold — it never
presses Publish, and visibility is still asked. Fall back to the manual steps below when the
extension cannot find a field, which means YouTube changed the page.

## Inputs

A clip number, e.g. "#47". Resolve it from the running app:

```sh
curl -s http://127.0.0.1:4317/api/state | python3 -c "import sys,json;c=[x for x in json.load(sys.stdin)['clips'] if x.get('number')==47][0];print(c['id'],c['url'],c.get('captionFile'))"
```

That gives the clip id. The two files live in the app's data directory:

- video: `data/<id>/clip.mp4`
- caption: `data/<id>/caption.txt`

`caption.txt` is the source of truth for the wording. Its shape:

```
<title line>

--- DESCRIPTION ---

<description, including the hashtag block>

--- TAGS ---

<comma-separated tags>
```

Take the title from line 1 and the description from the `--- DESCRIPTION ---` block. **Do not rewrite
them** — they are generated by `youtube-meta.mjs` from the stream listing and the clip's transcript,
and already have the emoji, hashtags and source credit. The `--- TAGS ---` block is for the API path
and is not entered in the Shorts flow.

If the title is over 100 characters, YouTube will reject it — trim at a word boundary and say so.

## Steps

1. Resolve the clip number to its id, and read `caption.txt`. Confirm the video file exists.
2. Open YouTube Studio in the browser the user is signed into (Claude in Chrome — their real browser —
   not the built-in pane, which has no YouTube session). Go to `studio.youtube.com`.
3. Confirm the active channel. If it is not the intended one, stop and ask.
4. **Ask for approval now**, quoting: clip number, title, visibility, and the filename.
5. Create → Upload videos, and attach `data/<id>/clip.mp4`.
6. Fill the form:
   - **Title**: line 1 of `caption.txt`
   - **Description**: the `--- DESCRIPTION ---` block verbatim
   - **Audience**: *No, it's not made for kids* — always
   - The clip is 540×960 and under 3 minutes, so YouTube treats it as a **Short** automatically.
     Do not fight the aspect ratio or add a `#Shorts` tag by hand; the description already carries one.
   - **Thumbnail / playlist**: leave alone unless asked.
7. Visibility: **ask, don't assume** — the user has not set a standing default. Offer Public, Unlisted
   or Private, and default to Private if he does not say.
8. Publish only after the yes from step 4 (and step 7 if visibility was still open).
9. Report back the video URL, the visibility it ended up with, and the clip number.

## After uploading

Clipcrow does not record manual uploads — `clip.upload` stays empty because that field is only set by
the API path. Note in your reply which clip numbers have been uploaded so they are not sent twice,
and keep a running list within the session.

## Choosing clips

Most clips are `reason: "Audio peak"` and many are noise. Unless the user names a number, do not pick
on your own — list a few candidates with their numbers, titles and spoken lines, and let him choose.

## Open questions (ask once, then record the answer here)

- Default visibility for clips — currently unset, so each upload asks.
- Whether a playlist or custom thumbnail should ever be set.
- Whether uploads should be scheduled rather than published immediately.
